AI-Assisted QA Automation

From Plain English Test Steps to Selenium Java

This web app explains how an LLM-powered agent can translate manual test cases into Selenium Java scripts, and where this approach fits in a real Jenkins CI/CD workflow.

Try the Translator Demo

1) What the system actually does

Read Test Case

Loads a plain English test case from TXT/JIRA/Confluence data.

Send to LLM

A Python agent prompts GPT (or local LLM) as a test-case-to-code translator.

Generate Java

Produces Selenium Java test classes with assertions and common framework patterns.

Save Script

Writes generated code as .java files to the automation repository.

Plain English Steps → Python Agent → OpenAI API → Selenium Java (.java)

2) Where this is useful in real projects

Test Cases → AI Generates Selenium Scripts → Git Repo → Jenkins Pipeline → Reports
  • Fast bootstrap of repetitive test scripts.
  • Converts manual QA assets into automation starters.
  • Speeds up iteration when requirements change.

Engineers still own locator quality, framework design, flakiness control, and CI integration.

3) Useful vs demo-only reality

Area Useful in production Demo limitation
Locators AI drafts selectors quickly May guess wrong IDs/XPath and break often
Framework Can scaffold Page Objects and tests Often dumps one large file
Tooling Can suggest Maven/TestNG/Allure setup Doesn't wire everything automatically
Maintenance Helpful for refactor suggestions Humans still needed for stable suites

4) Better architecture for a serious portfolio project

Recommended Stack

  • Python AI agent
  • OpenAI API or local LLM
  • Selenium Java + TestNG + Maven
  • GitHub + Jenkins + Allure reports

Upgraded Flow

  1. Read test case from TXT/JIRA
  2. Generate Page Object + Test class + locator proposals
  3. Commit/push to GitHub automatically
  4. Jenkins executes nightly and publishes reports
